# TinyInfer G0.5 Closeout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the unverified G0.5 candidate, prove it in a native WSL2 worktree, and publish an evidence-backed `v0.1.0-g0.5` milestone without claiming that Phase 1/G1 is complete.

**Architecture:** Keep capability inspection, GPU correctness, gate orchestration, and evidence reporting as separate components. Result success is derived from error/exit-code facts rather than stored independently; the verifier executes fixed commands and stops at the first failure. Code is repaired in the isolated Windows worktree, transferred by Git bundle to a native Linux worktree, and accepted only from fresh WSL evidence.

**Tech Stack:** Python 3.11, pytest, Ruff, Mypy strict mode, uv, PyTorch CUDA, Triton, Git worktrees, WSL2 Ubuntu-22.04.

## Global Constraints

- Milestone name is exactly `G0.5 Linux/GPU Environment Baseline`.
- Final annotated tag is exactly `v0.1.0-g0.5`.
- `v0.1.0-phase1` must not survive the final local/remote state.
- Do not implement R4, model loading, prefill/decode, KV cache, scheduling, serving, or performance kernels.
- Do not overwrite or delete uncommitted files in `D:\project\TinyInfer`.
- GPU acceptance must run in a native Linux worktree under `/home/administrator/projects/TinyInfer/.worktrees/`.
- Do not install NVIDIA Linux drivers inside WSL.
- Do not downgrade BF16 tests to FP16/FP32.
- Do not auto-commit, tag, push, install dependencies, or download models from a verifier.
- Stop publication if GitHub access is unavailable or remote refs change unexpectedly.
- Every completion claim requires a current command, exit code, and key output.
